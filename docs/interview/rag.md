# 基本流程

![v2-035e960d115f65b752e29a39768255ad_720w.webp](RAG/v2-035e960d115f65b752e29a39768255ad_720w.webp)

- 通过某种方式召回文档
- 将召回的文档和语言模型的内部知识结合，生成问题的答案

# 核心任务

- 去噪：召回的信息中，越少的**无关、矛盾**信息越好
- 推理：整合多个来源的信息，生成有依据的输出

# 知识融合

- 输入侧：检索到的文档和原始的query拼成一个prompt
- 输出侧：输出logits的时候，整合检索的知识，对模型的分布进行一个影响
- 中间层：外部知识的embedding和模型隐藏状态进行融合

# 精确意图理解

- **查询分解：**把一个问题分解为多个，一个query有可能不能在单跳完成，需要分解为多次，每次查询不同的内容
- **查询重写：**更精细化用户的问题，把用户友好的问题改为检索友好的问题，防止检索到太多的噪声文件：
    - 多轮对话中，可能有**代词**，比如“它是什么”，模型需要在上下文中找到“它”的对应
    - 多轮对话中，还可能有很多词语的**省略**，模型得理解内容，补充缺失的信息
    - 解决**拼写错误**

# 召回

## 块划分

为什么需要块划分：

- **长度有限：**嵌入模型的长度有限，推理用的LLM长度有限，如果文本太长，没法装到模型里面
- **突出重点：**一个长文本中，往往有多个主题，如果直接拿长文本作为召回的内容，语义会平均化（没有重点），有可能导致query和所有文本的相似度都比较类似，没有重点
- **降噪：**长文本块中存在很多无关信息，无意义信息，分块可以降低噪声
- **方便引用：**如果文本是按照自然段、章节划分，那么可以在回复中进行引用和高亮

## 多路

- 稠密向量embedding，进行词嵌入的计算，计算相似度
- 稀疏向量表示：BM25
- 查询时召回路径的增加：
    - 同义改写召回：同义/表述/别名/缩写的多版本查询
    - 让模型根据已有知识，生成一个答案，根据这个答案再进行召回
    - 利用初次命中的文档中的相关信息，再进行重复检索
- 根据时间、语言类型等文本的基类型进行召回

# BM25

## 前身TF-IDF（词频-逆文档频率）：衡量单词和文档的相关性

即TF*IDF，给定语料库C，TF-IDF可以衡量某个单词和C中某个文档的相关程度：**如果某个词语在当前文档中很常见，但是在其他文档中不常见，说明这个词和当前文档的相关性很高**

- 词频（TF）：在文本中，某个词出现的频率
- 逆文档频率（IDF）：+1防除零，逆文档频率越小，包含这个词语的文档越多

## 衡量句子和文档的相关性

![image.png](RAG/image%201.png)

- 分词
- 针对某一个文档D，计算词和文档相关性的加权平均
- idf作为权重，如果单词是稀有词，那么单词的权重就要高
- tf饱和项k1：
    - 如果词频非常高，会让收益慢慢递减，最大收敛到k1+1（磁盘由0到1，和由20到40是不一样的，后者的信息量较少）
    - 如果词频较低，刚开始收益是相对较高的
    - k1越小，就越快饱和
- 长度归一项：越长的文本，里面本身就有更多的词，所以需要对长文本的词频进行惩罚
