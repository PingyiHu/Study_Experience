# 和其他的业务方要争研发资源应该怎么办

我觉得和业务方协调资源是常见情况，关键不在“争”，而在“**沟通和协同**”。

我会先了解双方的项目目标和优先级，评估当前任务对整体业务的**价值和时效性**，然后和业务方**明确哪些资源是关键瓶颈**。

如果资源确实有限，我会提出阶段化或轻量化的方案，**尽量通过技术优化来缓解冲突**。

在我看来，目标不是谁拿更多资源，而是让公司整体效益最大化。只要逻辑清晰、沟通透明，大家通常都能达成共识。

这段经历让我学会了**目标管理和自我优化**，也让我更加坚定地相信解决问题的**方向很重要，拆分和计划很重要**

# 实习的项目中遇见的最大的困难是如何解决的

我在微软实习时参与的项目使用了一个叫 VERL 的强化学习框架，这是一个**高度模块化、多进程分布式的系统**。我的任务是修改这个框架以适应我的多智能体训练。

在我实习的时候，这个框架刚发布，资料非常少，代码量又大，调试难度很高，这也是我遇到的最大困难。

当时我没有急着修改代码，而是从整体流程入手，**理清框架的执行逻辑**，然后聚焦于我负责的模块。

在模块内部，我通过逐步保存中间变量、记录输入输出形状、绘制流程图等方式，**一点点梳理清楚每个关键组件的功能和依赖关系**。我还把理解过程做成笔记，形成了模块级的“可追踪执行链”。

这次经历让我意识到，面对复杂系统时，**最重要的是系统化分析和结构化拆解的能力**，这也成为我后续处理工程问题的习惯。

# 如何看待加班

我能理解在项目节点紧、任务集中的时候，适度加班是正常的，也是团队协作的一部分。

我平时的习惯是尽量提高工作效率，把问题在白天及时沟通、及时解决，减少不必要的加班。

我更倾向于**高效工作 + 合理加班**，而不是“被动熬夜式加班”。

# 如何平衡技术的深度和广度

我认为技术的深度和广度是相辅相成的。

我通常会先在一个方向上深入学习，比如强化学习中不同算法的原理和机制，先把核心思想吃透。

在此基础上，我会去了解算法在实际落地中的工程细节，比较不同实现方式的共性和差异，重点学习主流的方案。

这样既能保证对原理的深入理解，也能在工程实践中具备更全面的视角。

# 携程的企业文化

携程在其官网和公开资料中，常用 “CTRIP” 五个字母来表达其价值观：

- **C – Customer（客户）**：以客户为中心
- **T – Teamwork（团队）**：紧密无缝的合作机制
- **R – Respect（敬业）**：一丝不苟的敬业精神
- **I – Integrity（诚信）**：真实诚信的合作理念
- **P – Partner（伙伴）**：伙伴式的“多赢”合作体系
