# How to Write a Paper

> 论文写作顺序与阅读顺序不同。以下推荐的写作流程适用于 AI/安全领域的研究论文。

## 推荐写作顺序

**不要从 Introduction 开始写！** 按照以下顺序写作，每一步都建立在前一步的基础上：

```
调研（Survey）→ Related Work → Threat Model → Method → Experiments → Discussion → Introduction → Abstract → Conclusion
```

### 第一步：调研（Survey）

在动笔之前，充分了解领域现状：

- 阅读目标会议/期刊近年录用的论文，了解其风格和偏好
- 梳理相关工作，明确你的工作与现有方法的区别
- 确定你的贡献点（contribution）是什么

### 第二步：Related Work（相关工作）

先写 Related Work 的好处：
- 强迫你系统梳理领域现状
- 明确定位你的工作在已有研究中的位置
- 避免遗漏重要参考文献

**写作要点：**
- 按主题组织，而非简单罗列
- 突出与本文方法的区别和联系
- 指出现有方法的不足（gap），为你的方法建立动机

### 第三步：Threat Model（威胁模型）

> 适用于安全领域的论文

Threat Model 定义了你的方法所面对的安全假设和约束条件：

- **攻击者能力**：攻击者能做什么？不能做什么？
- **攻击目标**：攻击者想要达到什么目的？
- **系统假设**：系统中哪些组件是可信的？哪些是不可信的？

清晰的 Threat Model 让审稿人理解你的方法在什么场景下有效。

### 第四步：Method（方法）

方法部分是论文的核心。写作要点：

- **先给直觉，再给形式化**：用通俗语言解释核心思想，然后再给出数学定义
- **先总后分**：先给出整体框架，再详细描述各个组件
- **符号一致**：定义清晰的符号系统，全文保持一致
- **动机明确**：每个设计选择都应该有理由

### 第五步：Experiments（实验）

好的实验设计应回答以下问题：

| 实验类型 | 回答的问题 |
|:---|:---|
| 主实验 | 你的方法整体效果如何？（与 SOTA 对比） |
| 消融实验 | 每个组件的贡献是什么？（ablation study） |
| 参数敏感性 | 关键参数如何影响性能？ |
| 案例分析 | 定性结果能否支撑你的论点？ |

**重要提示：**
- 所有比较必须公平（相同数据划分、相同预处理）
- 报告均值和标准差，进行统计显著性检验
- 保存所有实验配置，确保可复现
- 图片保存为 PNG 格式，不要用 JPG（JPG 默认 80% 压缩率）

### 第六步：Discussion（讨论）

Discussion 部分讨论实验结果的意义和局限性：

- 结果说明了什么？有什么启示？
- 方法的局限性是什么？在什么场景下可能失效？
- 未来工作方向

### 第七步：Introduction（引言）

现在你已经清楚地知道自己做了什么、结果如何，可以写出精准的 Introduction：

1. **第一段**：问题背景，引起兴趣
2. **第二段**：现有方法及其不足（建立 gap）
3. **第三段**：本文的核心思路（high-level idea）
4. **贡献列表**：用条目形式明确列出 3-4 个贡献

### 第八步：Abstract（摘要）

摘要决定审稿人是否愿意仔细阅读你的论文。结构化写法：

1. **问题**：一句话说明研究问题和重要性
2. **现有方法的不足**：一句话指出 gap
3. **本文方法**：1-2 句描述核心思路
4. **关键结果**：1-2 句给出最重要的实验数字
5. **意义**：一句话总结贡献的影响

### 第九步：Conclusion（结论）

- 总结主要贡献和发现
- 讨论局限性（诚实面对）
- 展望未来工作
- **不要**重复摘要内容

## AI/安全论文写作要点

### 清晰性优先

- 每段第一句应是该段的核心观点
- 一个段落一个主题，避免"万能段落"
- 使用主动语态：*We propose...* 优于 *It is proposed that...*
- 避免长句和嵌套从句，审稿人没有时间反复阅读

### 图表规范

- 坐标轴必须标注名称和单位
- 图例清晰，不同曲线/柱子易于区分
- 字体大小在缩小到单栏宽度后仍可阅读
- 表格中最佳结果**加粗**，次优结果加下划线
- 使用"图形摘要"（graphical abstract）—— 用一张图概括论文核心思想

### 安全论文特殊要求

- **Threat Model 必须清晰**：审稿人首先看你的安全假设是否合理
- **攻击场景要具体**：不要泛泛而谈，给出具体的攻击场景和例子
- **防御要全面**：讨论可能的绕过方法和对策
- **实验要可复现**：提供代码和数据集，或详细的复现步骤

### AI/ML 论文特殊要求

- **数据集说明**：来源、规模、划分方式、预处理
- **基线选择**：选择合适的 SOTA 方法作为对比
- **超参数**：列出所有重要超参数及其选择理由
- **计算开销**：报告训练/推理时间和资源消耗
- **消融实验**：证明每个组件的贡献

## 常见拒稿原因

1. **贡献不清晰**：审稿人读完不知道你做了什么
2. **Threat Model 不合理**：安全假设过强或过弱
3. **缺少相关工作讨论**：没有说明与现有方法的区别
4. **实验不充分**：缺少消融实验、统计检验或公平比较
5. **写作质量差**：语法错误、逻辑混乱、图表不清
6. **过度宣称**：结论超出了实验支持的范围

## 投稿前检查清单

- [ ] 标题是否简洁且包含关键词？
- [ ] 摘要是否包含问题、方法、结果、意义？
- [ ] Threat Model 是否清晰定义？（安全论文）
- [ ] 引言是否清楚列出贡献？
- [ ] 相关工作是否突出了与本文的区别？
- [ ] 方法部分是否先给直觉再给形式化？
- [ ] 实验是否有消融研究和统计检验？
- [ ] 图表是否清晰、标注完整？
- [ ] 是否检查了拼写和语法？
- [ ] 参考文献格式是否一致？
- [ ] 是否遵守了页数限制和格式要求？
- [ ] 代码和数据是否可以公开？（如适用）
