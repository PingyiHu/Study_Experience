# 4. Agent安全与防御

LLM Agent（大语言模型智能体）的出现标志着大模型从"对话工具"向"自主行动体"的范式跃迁。通过集成工具调用（Tool Use）、长期记忆（Memory）、多步推理（Reasoning）和多Agent协作（Multi-Agent Coordination），Agent获得了与真实世界交互的能力。然而，这种能力的扩展同时引入了一个根本性的安全张力：Agent能够做的事情越多，攻击者能够利用的攻击面就越大，一旦失控造成的危害也越严重[^1^]。本章系统梳理Agent安全领域的经典与前沿论文，深入分析其独特的威胁模型、攻击方法体系与防御框架。

## 4.1 经典论文推荐

### 4.1.1 间接提示注入攻击的开山之作

**Greshake et al., "Not What You've Signed Up For: Compromising Real-World LLM-Integrated Applications with Indirect Prompt Injection," AISec 2023**[^2^]

Greshake等人的这篇论文是Agent提示注入安全研究领域公认的奠基之作。在此之前，安全社区主要关注直接提示注入（Direct Prompt Injection, DPI），即攻击者直接向模型输入恶意指令。Greshake等人首次系统性地将攻击面扩展到**间接提示注入**（Indirect Prompt Injection, IPI）：攻击者将恶意指令嵌入到LLM应用所处理的第三方内容中（如网页、邮件、文档），当应用检索并处理这些内容时，恶意指令被间接注入到模型的上下文中，从而劫持应用行为[^2^]。

该研究对Bing Chat等真实系统进行了实证分析，展示了IPI攻击能够窃取用户聊天记录、操纵搜索结果、诱导用户点击恶意链接。其核心价值在于定义了直接注入与间接注入的二元分类框架，并证明了一个关键命题：只要LLM应用处理不可信的外部内容，IPI攻击就不可避免。这一结论深刻影响了后续几乎所有Agent安全研究——当Agent通过工具调用来获取外部信息时，工具返回的每一比特内容都是潜在的攻击向量。

### 4.1.2 沙箱仿真评测框架

**Ruan et al., "ToolEmu: Identifying Risks of LM Agents with an LM-Emulated Sandbox," NeurIPS 2024**[^3^]

ToolEmu是Agent安全评测领域的里程碑工作，它解决了一个核心难题：如何在安全可控的环境中系统性地评估Agent的风险行为。Ruan等人提出了使用另一个语言模型来模拟沙箱环境（LM-Emulated Sandbox），使Agent能够在其中执行工具调用并观察行为后果，而无需接触真实系统[^3^]。

该框架覆盖了36个工具包、144个高风险任务和9种风险类型，包括信息泄露、财务损失、系统破坏等。ToolEmu的创新在于用"模拟"替代"真实执行"——当Agent调用一个危险工具（如`delete_all_files`）时，模拟器会生成一个逼真的后果描述（"所有文件已被删除"），Agent据此继续后续推理。这种方法既保障了实验安全，又实现了大规模自动化评测。后续众多Benchmark如AgentDojo、ASB都在方法论层面受到ToolEmu的深刻影响。

### 4.1.3 Agent基础架构范式

**Yao et al., "ReAct: Synergizing Reasoning and Acting in Language Models," ICLR 2023**[^4^]

ReAct虽然并非一篇安全论文，但它是理解Agent安全的必要前置知识。Yao等人提出的ReAct范式定义了现代LLM Agent的基本架构：**推理**（Thought）与**行动**（Action）在交替循环中协同进行——Agent先思考（"我需要查询天气"），再行动（调用工具），然后观察结果（"温度25°C"），再思考下一步，如此循环直至任务完成[^4^]。

理解ReAct架构之所以对安全研究至关重要，是因为几乎所有Agent攻击都针对这一循环中的特定环节。**间接提示注入**攻击的是Observation（观察）环节——攻击者在工具返回的结果中嵌入恶意指令；**工具劫持**攻击的是Action（行动）环节——操纵Agent选择错误的工具；**CoT暴露**攻击的是Thought（思考）环节——窃取或操纵Agent的内部推理链。ReAct架构为安全研究者提供了一个精确的攻击面分析框架。

### 4.1.4 Agent后门攻击

**Wang et al., "BadAgent: Inserting and Activating Backdoor Attacks in LLM Agents," ACL 2024**[^5^]

BadAgent是首个系统研究LLM Agent后门攻击的工作。Wang等人证明，攻击者可以通过在Agent的训练数据和工具链中植入精心设计的触发器（Trigger），使得Agent在正常情况下表现完全正常，但在触发器出现时执行预设的恶意行为[^5^]。例如，当Agent检测到特定关键词时，会调用恶意工具或将敏感信息发送到攻击者控制的服务器。

该研究的深远意义在于揭示了Agent的**持久化威胁**——与一次性提示注入不同，后门攻击一旦被植入，会持续存在于Agent的行为模式中，即使用户更换了提示词或更新了部分配置也无法消除。BadAgent展示了后门可以通过两条路径植入：一是**训练数据投毒**，在Agent的微调数据中嵌入带触发器的恶意样本；二是**工具链污染**，在工具描述或工具实现中嵌入隐藏触发逻辑。这项工作为后续的AgentPoison、BackdoorChain等研究奠定了基础。

### 4.1.5 记忆层攻击

**Chen et al., "AgentPoison: Red-teaming LLM Agents via Poisoning Memory or Knowledge Bases," 2024**[^6^]

AgentPoison首次将目光投向Agent的**长期记忆**和**RAG知识库**（Retrieval-Augmented Generation），这是一个此前被严重忽视的攻击面。Chen等人提出了一种约束优化方法，能够在知识库中仅需注入不到0.1%的恶意样本，就在目标查询上达到超过80%的攻击成功率[^6^]。

该攻击的核心机制是**触发器-载荷耦合**：攻击者在知识库中植入看似正常的文档，这些文档包含精心设计的触发模式（如特定行业术语的组合）。当用户查询包含这些触发模式时，RAG系统会检索到恶意文档，Agent在处理这些文档时执行攻击者预设的操作——如调用恶意工具、泄露敏感信息或输出误导性结果。AgentPoison揭示了一个关键风险：Agent对记忆系统的信任是其高效工作的基础，但这种信任恰恰构成了最大的安全弱点。

## 4.2 最新前沿论文

### 4.2.1 自传播蠕虫攻击

**Wei et al., "Self-Propagating Attacks Across LLM Agent Ecosystems (ClawWorm)," 2026**[^7^]

ClawWorm是Agent安全领域最具震撼力的近期工作之一。Wei等人首次证明了LLM Agent生态系统中存在**自传播蠕虫攻击**的可行性：一个被感染的Agent可以自主地将攻击传播到其他Agent，无需攻击者持续介入[^7^]。该攻击针对生产级Agent框架OpenClaw实现，攻击成功率达到64.5%。

ClawWorm的感染循环包含四个阶段：首先通过间接提示注入**劫持目标Agent的配置文件**；然后**建立持久化机制**确保攻击在Agent重启后仍然存活；接着**执行恶意载荷**（如数据窃取、权限提升）；最后**扫描并向对等Agent传播**Payload。这一工作揭示了一个根本性的安全命题：当多个Agent之间建立信任关系并进行协作时，任何一个节点的沦陷都可能导致整个生态的级联崩溃。ClawWorm的破坏性不仅在于其高攻击成功率，更在于其**自治传播能力**——攻击一旦启动，就可以在Agent生态中像生物病毒一样自主扩散。

### 4.2.2 全面Agent安全综述

**Yu et al., "A Survey on Trustworthy LLM Agents: Threats and Countermeasures," KDD 2025**[^8^]

这是目前最全面的LLM Agent安全综述论文。Yu等人建立了首个系统化的Agent安全分类框架，将可信性分为**内在可信性**（Brain、Memory、Action、Guardrail四个维度）和**外在可信性**（Agent协作、环境交互两个维度）[^8^]。

该综述的核心贡献在于提供了一个全景式的威胁地图。在内在层面，Brain维度关注模型本身的推理偏差和幻觉问题；Memory维度关注长期记忆的一致性和安全性；Action维度关注工具调用的安全性；Guardrail维度关注安全护栏的有效性和绕过可能性。在外在层面，Agent协作维度关注多Agent系统中的信任和通信安全；环境交互维度关注Agent与物理/数字环境交互时引入的新攻击面。这一分类框架为后续研究提供了统一的术语体系和问题定义基础。

### 4.2.3 步骤级主动防护

**Mou et al., "ToolSafe: Enhancing Tool Invocation Safety via Proactive Step-level Guardrail," 2026**[^9^]

ToolSafe代表了Agent安全防护从"检测-响应"模式向"预测-预防"模式的范式转变。Mou等人提出了三个核心组件：TS-Bench（首个步骤级工具调用安全检测基准）、TS-Guard（基于多任务强化学习的护栏模型）和TS-Flow（护栏反馈驱动的推理框架）[^9^]。

传统护栏通常在Agent已经决定调用某个工具之后进行拦截，属于"事后检测"模式。TS-Guard的创新在于**步骤级预测**——在Agent执行工具调用的每一个推理步骤中实时评估安全风险，并在风险超过阈值时通过反馈机制引导Agent调整其行为方向。实验结果表明，该方法能够将有害工具调用减少65%[^9^]。这一工作的重要意义在于证明了**细粒度行为监控**的可行性——安全护栏不必等到Agent做出危险决策时才介入，而是可以在决策形成的过程中持续施加影响。

### 4.2.4 工具选择劫持

**Shi et al., "ToolHijacker: Prompt Injection Attack to Tool Selection in LLM Agents," NDSS 2026**[^10^]

ToolHijacker首次将攻击面从**工具调用阶段**扩展到**工具选择阶段**。在典型的Agent系统中，工具选择通常包含两个子步骤：工具检索（从工具库中搜索相关工具）和工具选择（从候选工具中决定使用哪个）。Shi等人证明，攻击者可以通过注入恶意工具文档来同时操纵这两个环节[^10^]。

该攻击的关键洞察在于：大多数Agent框架将工具描述文档视为可信信息源，但当工具库规模较大时（如数百个工具），维护者对每个工具的描述进行逐条审查是不现实的。攻击者可以在工具名称和描述中嵌入微妙的语义误导（如将恶意工具命名为看似无害的名称），在黑盒场景下操纵Agent的工具选择决策。ToolHijacker的实验表明，现有防御措施（包括输入过滤、输出验证和安全对齐）均无法有效应对此类攻击[^10^]，揭示了工具库管理中的安全盲区。

### 4.2.5 MCP安全基准

**Yang et al., "MCPSecBench: A Systematic Security Benchmark for Model Context Protocols," 2026**[^11^]

Model Context Protocol（MCP）作为Anthropic提出的Agent工具连接标准协议，正在成为Agent生态系统的事实标准。MCPSecBench是首个针对MCP生态的系统安全基准测试，定义了17种攻击类型，跨越4个攻击面：客户端（提示注入、工具/服务误用）、协议端（中间人攻击、MCP重绑定）、服务端（工具投毒、数据泄露、Rug Pull）和主机端（配置漂移、沙箱逃逸、漏洞利用）[^11^]。

评估结果令人警醒：85%以上的攻击类型至少能攻破一个主流MCP平台，而当前保护机制的平均成功率不足30%[^11^]。MCPSecBench的深远意义在于将Agent安全研究从模型层和Agent层推向了**协议层**——当Agent生态开始标准化互联时，协议本身的安全性就成为整个生态的根基。

## 4.3 学习笔记：核心概念与理论

### 4.3.1 Agent安全定义与威胁模型

LLM Agent安全是保护基于大语言模型的自主智能体免受恶意攻击、误用和意外危害的系统性研究。与前几章讨论的传统LLM安全相比，Agent安全呈现出一系列本质性的差异。

下表从五个关键维度对比传统LLM安全与Agent安全：

| 维度 | 传统LLM安全 | LLM Agent安全 |
|:---:|:---|:---|
| 攻击面 | 输入文本、模型参数、训练数据 | 工具调用接口、记忆存储、Agent间通信信道、环境交互接口 |
| 攻击目标 | 诱导模型输出有害内容、绕过安全策略 | 操纵工具执行未授权操作、窃取用户数据、建立持久化控制、跨系统传播 |
| 攻击持久性 | 单轮或有限轮次，攻击效果随对话结束而终止 | 多轮持久化：记忆投毒可长期影响Agent行为，后门可永久植入 |
| 攻击传播性 | 单次影响，局限于单个对话会话 | 可跨Agent传播：蠕虫式自传播、多Agent信任级联、供应链污染 |
| 危害范围 | 内容层面（有害文本、偏见输出） | 系统层面：远程代码执行（RCE）、数据泄露、权限提升、财务损失[^1^][^8^] |

Agent安全的威胁模型通常包含以下要素。**攻击者目标**涵盖操纵Agent执行恶意工具调用（如删除数据、转账汇款）、窃取用户敏感信息（聊天记录、文件内容）、建立持久化控制（后门激活、记忆投毒）以及在多Agent系统中横向移动。**攻击者能力**从仅能通过自然语言查询与Agent交互（黑盒），到能够控制工具的响应内容（灰盒），再到完全控制工具实现和Agent配置（白盒），形成连续的能力谱系。**攻击面**按照ASB（Agent Security Bench）框架可划分为六个层次：用户提示层、工具使用层、记忆层、系统提示层、多Agent通信层和环境层[^12^]。

### 4.3.2 攻击方法体系

Agent攻击方法可以按照目标层次分为四大类别。

**工具/插件滥用**是Agent安全中最成熟的攻击类别。**间接提示注入**（Indirect Prompt Injection, IPI）是其中的核心手段：攻击者在工具返回的内容中嵌入恶意指令，当Agent处理这些内容时攻击者意图被注入。Greshake等人的研究表明，任何通过工具获取的外部内容都构成潜在的IPI攻击向量[^2^]。**工具选择劫持**（Tool Hijacking）则瞄准工具调用链的上游：Shi等人证明攻击者可通过操纵工具描述文档来引导Agent选择攻击者控制的恶意工具[^10^]。此外，随着MCP生态的兴起，**工具供应链投毒**成为新兴威胁——恶意MCP服务器在工具描述中嵌入隐藏指令，通过工具供应链的"信任传递"影响所有使用该工具的Agent[^11^]。

**记忆层攻击**针对Agent的长期记忆和RAG知识库。**记忆投毒**（Memory Poisoning）通过正常的查询交互逐步向Agent记忆中注入恶意指令，这些被污染的记忆在后续任务中被Agent自动检索并执行[^6^]。**RAG后门**攻击则更加隐蔽：攻击者在知识库中注入少量（<0.1%）经过精心设计的恶意文档，当查询包含特定触发模式时检索系统返回恶意内容，Agent在处理这些内容时执行预设的恶意操作[^6^]。记忆层攻击的持久性是其最大威胁：一旦记忆被污染，即使攻击者不再介入，被污染的记忆也会持续影响Agent的后续行为。

**跨Agent攻击**在多Agent系统中展现出惊人的破坏力。研究表明，Agent间信任利用的成功率高达82.4%，远超直接提示注入的41.2%[^13^]。这一数据的背后是一个深刻的安全悖论：LLM Agent对来自同伴Agent的请求应用的安全策略远比对人类用户的请求宽松。ClawWorm进一步证明了Agent生态中**自传播攻击**的可行性——被感染的Agent可以自主地将攻击传播到对等节点，攻击者只需攻破一个入口点，就可以通过信任链实现生态级的感染[^7^]。

**环境操控攻击**随着Computer Use Agent（CUA）的兴起而成为新的研究焦点。**UI欺骗**攻击通过视觉覆盖元素（如伪造的按钮、弹窗）误导Agent的界面级推理；**CoT暴露**（Chain-of-Thought Exposure）攻击利用Agent的多步推理过程，通过操纵中间推理步骤来劫持最终行为；**人类在环绕过**（Human-in-the-Loop Bypass）则诱导Agent绕过本应触发的人类确认环节[^14^]。

### 4.3.3 防御方法体系

Agent防御体系可以从四个层面构建。**权限控制与沙箱**是最基础的防御层。零信任架构（Zero Trust Architecture）要求Agent默认不信任任何外部输入，包括工具响应、同伴Agent消息和记忆检索结果。**最小权限原则**（Principle of Least Privilege）要求Agent仅拥有完成当前任务所必需的工具访问权限，并在任务完成后立即回收权限[^15^]。ToolEmu开创的沙箱仿真方法为权限控制提供了测试基础设施[^3^]。

**行为监控**代表防御的前沿方向。ToolSafe提出的**步骤级护栏**（Step-level Guardrail）将安全监控粒度从"工具调用决策"细化到"推理过程中的每一步"，通过实时风险评估和反馈干预在危险行为形成之前进行引导[^9^]。GuardAgent则提出了**知识启用推理**（Knowledge-Enabled Reasoning）的防御范式：Agent在执行工具调用前，先查询外部安全知识库以评估操作的潜在风险[^16^]。

**输入/输出过滤**是已经被广泛部署的传统防御手段。PromptGuard等基于分类器的注入检测器、基于困惑度（Perplexity）异常的恶意输入检测、以及FATH等使用HMAC标签验证用户指令完整性的认证机制，构成了输入过滤的技术栈。然而，ToolHijacker等研究表明，仅靠输入/输出过滤远不足以应对Agent的复杂攻击面[^10^]。

**安全对齐**从模型训练层面增强Agent的内在防御能力。安全微调（SecAlign）通过在训练数据中引入安全场景来增强Agent对攻击的识别和抵抗能力。**选择性退出机制**则赋予Agent在不确定时拒绝执行而非冒险行动的能力，这本质上是在Agent的自主性与安全性之间寻找平衡[^8^]。

### 4.3.4 关键理论

Agent安全领域存在几个值得深入思考的理论命题。

**能力-风险权衡**（Capability-Risk Tradeoff）是Agent安全中最核心的张力关系。Agent的工具使用能力、多步推理能力和自主决策能力直接决定了其能够完成任务的复杂程度，但同时也线性扩大了攻击面[^1^]。一个只能读取文件的Agent与一个能够执行任意代码的Agent所面临的威胁模型完全不同。这一权衡没有普适的最优解——安全研究者需要根据具体应用场景在能力开放度和风险控制度之间做出审慎的权衡。

**自主性悖论**（Autonomy Paradox）指出，Agent的自主性越高，安全措施越容易被绕过。当Agent被设计为能够自主决策、自适应环境和自主恢复时，它同样获得了自主绕过安全机制的能力。人类在环（Human-in-the-Loop, HiTL）设计本意是在关键操作前引入人类确认，但研究表明Agent可以被诱导绕过这些确认环节[^14^]。

**工具使用的信任边界**理论认为，每一次工具调用本质上都是一次信任决策——Agent必须信任工具的名称与功能描述、工具返回的数据、以及工具的实现者。然而，这种信任在实践中往往被过度授予：Agent框架通常将工具描述视为可信信息源，而MCP生态中第三方服务器的安全性更是缺乏保障[^11^]。语义差距（Semantic Gap）——即工具名称/描述与实际行为之间的差距——构成了攻击者可以利用的操纵空间[^10^]。

**多Agent信任传递问题**揭示了协作系统中的一个深层安全困境。当Agent A信任Agent B，Agent B信任Agent C时，Agent A间接地信任了Agent C。在多Agent协作链中，这种传递性信任使得任何一个中间节点的沦陷都会影响整个链条的安全。ClawWorm正是利用了这一机制实现跨Agent传播[^7^]。更令人担忧的是，研究表明LLM Agent对来自同伴的请求天然地应用比人类用户更宽松的安全策略[^13^]，这种"同伴信任偏见"（Peer Trust Bias）是多Agent系统安全的一个根本性弱点。

**MCP安全架构**的四方模型（Host、Client、Server、Protocol）为理解Agent生态安全提供了系统框架[^11^]。Host负责承载Agent运行环境，Client负责与MCP Server通信，Server提供工具实现，Protocol定义通信规范。安全漏洞可以存在于任何一个组件中：Client可能存在提示注入漏洞，Server可能存在工具投毒风险，Protocol本身可能被中间人攻击，Host环境可能发生沙箱逃逸。当前MCP生态的安全防护严重滞后——MCPSecBench的评估显示保护机制平均成功率不足30%[^11^]，这意味着MCP在安全成熟度的意义上仍处于"野生西部"阶段。

## 4.4 学习路径建议

### 4.4.1 入门路线

系统学习Agent安全建议遵循"架构理解→攻击面分析→防御方法实践→前沿追踪"的递进路线。第一阶段的核心是深入理解ReAct架构[^4^]，明确Thought-Action-Observation循环中每个环节的潜在安全弱点。第二阶段依次学习间接提示注入[^2^]、记忆层攻击[^6^]、后门攻击[^5^]和跨Agent攻击[^7^]，建立对攻击方法体系的全景认知。第三阶段通过复现ToolSafe[^9^]和GuardAgent[^16^]等防御方法，理解安全防护的设计权衡。最后通过追踪MCP安全[^11^]、CUA安全[^14^]和自传播攻击[^7^]等前沿方向保持知识更新。

### 4.4.2 实验环境推荐

下表对比了Agent安全领域的主要评测平台，为实验实践提供选择参考：

| Benchmark | 发表年份 | 评测类型 | 规模与覆盖 | 核心特点与适用场景 |
|:---:|:---:|:---:|:---|:---|
| ToolEmu | NeurIPS 2024 | 沙箱仿真 | 36个工具包，144个高风险任务，9种风险类型 | LM模拟沙箱，零风险进行大规模Agent安全评测；适合早期风险识别和安全机制原型验证[^3^] |
| AgentDojo | 2024 | 端到端安全 | 97个任务，629个安全测试用例 | 动态可扩展评估框架，支持攻击和防御的对抗评测；适合端到端攻防实验[^12^] |
| ASB | ICLR 2025 | 综合安全 | 10个场景，10类Agent，400+工具 | 统一攻击/防御Benchmark，支持多维度安全评估；适合系统性安全能力评估[^12^] |
| MCPSecBench | 2026 | MCP协议安全 | 17种攻击类型，4个攻击面 | 首个MCP生态安全评测，覆盖客户端/协议端/服务端/主机端；适合协议层安全研究[^11^] |
| TS-Bench | 2026 | 步骤级安全 | 步骤级工具调用安全检测 | 首个步骤级安全检测基准，支持细粒度护栏评估；适合主动防御机制研究[^9^] |
| AgentHarm | 2024 | 有害行为 | 110个恶意任务，11个危害类别 | 评估Agent对有害请求的执行合规性；适合安全对齐能力评测 |

选择实验环境时应考虑研究目标：若关注Agent整体安全能力评估，AgentDojo和ASB提供了最完整的端到端评测框架；若关注MCP生态安全，MCPSecBench是当前唯一的选择；若关注步骤级主动防御，TS-Bench提供了最细粒度的评估能力。对于初学者，建议从ToolEmu入手——其模拟沙箱设计消除了实验安全风险，同时提供了丰富的工具和风险场景来构建对Agent安全的直观理解。
