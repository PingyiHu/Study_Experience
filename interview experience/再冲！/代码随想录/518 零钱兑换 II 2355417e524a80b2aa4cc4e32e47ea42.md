# 518. 零钱兑换 II

Tags: 动态规划
URL: https://leetcode.cn/problems/coin-change-ii/description/

# 我的方法

在查找装满背包有多少种方法时，不需要再去考虑是否能装满背包，因为如果装不满ways一定是0

还需要注意int有可能不够装，需要更大的类型装

```cpp
class Solution
{
public:
    int change(int amount, vector<int> &coins)
    {
        vector<uint64_t> ways(amount + 1, 0);
    
        ways[0] = 1;
        for (int i = 0; i < coins.size(); i++)
        {
            for (int j = coins[i]; j <= amount; j++)
            {
                ways[j] += ways[j - coins[i]];
            }
        }

            return ways[amount];
    }
};
```

# 遍历方式带来的区别

## 先遍历物品，再遍历背包

for (int i = 0; i < coins.size(); i++)
            for (int j = coins[i]; j <= amount; j++)

这种情况下，永远是先把靠前的物品放入背包，然后再考虑之后的物品。因为不存在把后面的东西先放在包里的情况，东西放入背包总是有序的，因此求的是**组合数**。

## 先遍历背包，再遍历物品

for (int j = 0; j <= amount; j++)
            for (int i = 0; i < coins.size(); i++)

这种情况下，在序号较大的物品时候可能已经放入背包。当背包容量进一步扩充的时候，又会把序号较小的东西塞进去。会有乱序的情况发生，因此是求的是**排列数**。

## 如果是求的价值

不管是进行排列，还是进行组合，求价值的时候，最后最终的总价值是相等的。

## 如果求的是集合，并且顺序不同的集合不是同一个集合

这个时候就需要排列了。
