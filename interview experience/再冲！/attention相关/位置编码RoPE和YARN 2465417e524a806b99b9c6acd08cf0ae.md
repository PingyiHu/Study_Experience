## 位置编码的演化

位置编码最好的就是像数字一样，低位变化的频繁一些，而高位变化的缓慢一些，二进制（甚至是10进制）是满足这样的要求的。

- **二进制编码：**一开始想用二进制作为位置编码，但是二进制是不连续的
- **sin模拟二进制：**采用不同角速度的sin函数来模拟二进制编码，二进制是越高位（对应高维）变换越少；低位变化的多，同时sin函数还是连续的

    ![image.png](%E4%BD%8D%E7%BD%AE%E7%BC%96%E7%A0%81RoPE%E5%92%8CYARN/image%202.png)
    
- 选10000作为底数：因为周期函数，如果波长太小的话，位置靠后的token和位置考前的token可能会离得很近（浅黄和黑色）

## 推广到多维

如果应用RoPE，一般来说维度是**偶数**，推广到多维其实就是把一个词嵌入X，d维，看作d//2个二维坐标，对于另一个词嵌入Y也是同理：

- 以d=4，则(x0, x1)，(x2, x3)为两个向量，和Y那一侧的两个向量分别形成2组向量。

```python
# 生成旋转矩阵
def precompute_freqs_cis(dim: int, seq_len: int, theta: float = 10000.0):
    # 计算词向量元素两两分组之后，每组元素对应的旋转角度\theta_i
    # freqs = 1.0 / (theta ** (torch.arange(0, dim, 2)[: (dim // 2)].float() / dim))
    # 如果确保了dim为偶数可以像下面这么写
    freqs = 1.0 / (theta ** (torch.arange(0, dim, 2).float() / dim))
    # 生成 token 序列索引 t = [0, 1,..., seq_len-1]
    t = torch.arange(seq_len, device=freqs.device)
    **# outer是外积，一列乘以一行，算出每个token位置的一组旋转角度**
    # freqs.shape = [seq_len, dim // 2] 
    ****freqs = torch.outer(t, freqs).float()  # 计算m * θ

    # 计算结果是个复数向量
    # 假设 freqs = [x, y]
    # 则 freqs_cis = [cos(x) + sin(x)i, cos(y) + sin(y)i]
    **# 这里把极坐标1，freqs，变为复数坐标，形状为[seq_len, dim // 2]**
    freqs_cis = torch.polar(torch.ones_like(freqs), freqs) 
    return freqs_cis

def reshape_for_broadcast(freqs_cis: torch.Tensor, x: torch.Tensor):
		"""
		x的形状是[batch_sz, seq_len, dim//2]
		将预先计算好的旋转角度freqs_cis的shape与输入shape统一。
		freqs_cis的维数会变为和x一致
		其中第二维是freqs_cis.shape[0],最后一维是freqs_cis.shape[1],其余维度为1
		"""
		# 保证两者在hidden维和seq_len这两个维度相等
		# 如果应用多头attention需要把freq变为(1, seq_len, 1, dim//2)
		assert freqs_cis.shape == (x.shape[1], x.shape[-1])
    ndim = x.ndim
    shape = [d if i == 1 or i == ndim - 1 else 1 for i, d in enumerate(x.shape)]
    return freqs_cis.view(*shape)

# 旋转位置编码计算
def apply_rotary_emb(
    xq: torch.Tensor,
    xk: torch.Tensor,
    freqs_cis: torch.Tensor,
) -> Tuple[torch.Tensor, torch.Tensor]:
    # xq.shape = [batch_size, seq_len, head_num, head_dim]
    # xq_.shape = [batch_size, seq_len, head_num, head_dim // 2, 2]
    bz=xq.shape[0]
    head_num=xq.shape[1]
    seq_len=xq.shape[2]
    head_dim=xq.shape[3]
    
    # 把最后一维两两一组拆开
    xq_ = xq.reshape(bz, head_num, seq_len, head_dim//2, 2)
    xk_ = xk.reshape(bz, head_num, seq_len, head_dim//2, 2)
    
    # 转为复数域
    # xq_.shape = [batch_size, seq_len, head_num, head_dim // 2]
    xq_ = torch.view_as_complex(xq_)
    xk_ = torch.view_as_complex(xk_)
    
    # 不写了，当作在这个函数外已经把freqs_cis对齐到seqlen了
    # freqs_cis = reshape_for_broadcast(freqs_cis, xq_)
    
    # 应用旋转操作，然后将结果转回实数域
    # xq_out.shape = [batch_size, seq_len, head_num, head_dim]
    **# flatten指的是把2维即其之后压成一维**
    xq_out = torch.view_as_real(xq_ * freqs_cis).flatten(3)
    xk_out = torch.view_as_real(xk_ * freqs_cis).flatten(3)
    return xq_out.to(dtype=xq.dtype), xk_out.to(dtype=xk.dtype)
```

# RoPE外推存在的问题

RoPE直接进行外推，即在短序列训练，直接运用到长序列推理，效果很差：

- 高频处，旋转速度快，在远距离的情况下会出现相位重叠（位置信息会出现歧义），**主要关注近邻token的相对位置信息**：
    - 在计算很远的距离时，i-j本身就会跨越多个周期，**对远程的相对关系，高频参考意义较少**
    - 在计算近距离的关系的时候，如果把高频压缩了，那么相位就会很接近，从而较近距离的关系就会模糊
- 低频处，旋转速度慢，出现相位重叠的情况较少，主要负责长距离的位置信息，超长上下文的情况下，可能出现很多没有见过的相位，因此要进行内插
    - 也就是说在训练的时候，可能低频位置都没有完整转过一圈，而高频的位置的各种相位可能都见过了一次

## 平滑内插**NTK-Aware Interpolation**

直接给底数乘以了上下文的缩放比例：相当于频率高的地方插值很少，外推的部分很多；频率低的地方进行插值很多，外推的部分很少

![image.png](%E4%BD%8D%E7%BD%AE%E7%BC%96%E7%A0%81RoPE%E5%92%8CYARN/image%2021.png)

## **基于波长局部分段插值NTK-by-parts Interpolation**

NTK aware的劣势：

- 平滑的方式还是使得部分低频受到了压缩，局部位置的信息模糊
- 高频部分并不是完全的内推，也存在部分超出上限的相位

**对特高频和特低频分别进行完全的外推和内插，使得局部和全局信息得到更好的保留**

计算出每一个维度的波长（其实就是旋转的周期），获得**训练时文本上限长度和当前维度波长的比值r(d)（其实就是训练时当前这个频率下，转过了多少圈）**，规定α和β：

- 旋转的周期数小于α，说明频率太低，进行内插，完整地映射回训练时的区间
- 旋转的周期数大于β，说明转了很多圈，直接进行外推，自然地延长
- 周期在α，β之间，说明转速适中，就把内插和外推的结果进行加权平均，越靠近低频内插越多

## Yarn等于NTK by parts + temperature

- 内插之后，相当于把角度变小，相当于增大了QK的乘积
- NTK by parts+temperature，防止分布过于奇异
