# 广播机制的原理和作用

- 广播机制不会增加显存占用，是对数据的逻辑复制，也就是相同的计算多算了几次

下面用**一个具体例子**，把「广播机制」从「逻辑扩展」一直讲到「如何用**步长（stride）在底层不复制数据**地完成运算」。

（PyTorch 在 CPU 和 GPU 上用的都是同一种思想，只是底层代码不同，这里用 CPU 上的 C++ 实现思路来讲）

---

### 1️⃣ 例子：二维张量 + 一维向量

```python
A = torch.arange(6).reshape(2, 3)        # shape (2, 3)
B = torch.tensor([10, 20, 30])           # shape (3,)
C = A + B                                # 结果 shape (2, 3)
```

逻辑上我们先把 B 扩展成

```
[[10, 20, 30],
 [10, 20, 30]]
```

再按元素相加。

**但 PyTorch 不会真的开辟 6 个新元素，而是靠“步长”在循环里反复读取 B 里的 3 个数。**

---

### 2️⃣ 张量的物理存储（Storage + Stride）

- **Storage**：一块连续的 `float*` 内存，里面只有原始数据。
- **Stride**：一个整数数组，告诉我们在每个维度上“跳多少元素”才能走到下一个元素。

对上面的 `A` 和 `B`：

| 张量 | shape | stride | storage 内容 |
| --- | --- | --- | --- |
| A | (2,3) | (3,1) | [0,1,2,3,4,5] |
| B | (3,) | (1,) | [10,20,30] |
- 对 A：`A[i,j]` 的地址 = `A.storage + i*3 + j*1`
- 对 B：`B[k]` 的地址 = `B.storage + k*1`

---

### 3️⃣ 广播时的“虚拟”形状和步长

PyTorch 在内部先**对齐维度**（从右往左），然后**把长度为 1 的维度标成 stride=0**，

这样“重复读取”就实现了：

| 张量 | 对齐维度 | 广播后 shape | 广播后 stride |
| --- | --- | --- | --- |
| A | (2, 3) | (2, 3) | (3, 1) |
| B | (1, 3) | (2, 3) | (0, 1) ← 关键 |
- stride=0 的含义：在这一维上“走一步”其实**地址没变**，于是同一行被**复用**。
- 于是 `B[i,j]` 的地址始终是 `B.storage + 0*i + 1*j = B.storage + j`，
也就是第 0、1、2 列分别一直是 10、20、30。

---

### 4️⃣ 真正的三重循环（伪代码）

CPU 上最朴素的实现大概长这样：

```cpp
// A, B, C 的底层指针和 stride 都准备好了
float* a_ptr = A.storage;
float* b_ptr = B.storage;
float* c_ptr = C.storage;

for (int64_t i = 0; i < 2; ++i) {
  for (int64_t j = 0; j < 3; ++j) {
      // A[i,j] 的地址
      float* a_ij = a_ptr + i*A.stride[0] + j*A.stride[1];
      // B[i,j] 的地址（注意 stride[0]==0）
      float* b_ij = b_ptr + i*B.stride[0] + j*B.stride[1];
      // 计算并写结果
      *(c_ptr + i*C.stride[0] + j*C.stride[1]) = *a_ij + *b_ij;
  }
}

```

- 当 `i` 从 0 变 1 时，`b_ij` 仍然读的是 `[10,20,30]`，因为 `i*B.stride[0] = i*0 = 0`。
- 这样就**在不复制内存**的情况下完成了“把 B 扩展两行”的效果。

---

### 5️⃣ GPU 上的并行化

GPU 上不会用嵌套 for 循环，而是：

1. 启动一个 2×3 = 6 个线程的 grid；
2. 每个线程算自己的 `(i,j)`；
3. 用同样的 stride 规则在线程内部寻址，一样没有数据复制。

---

### 6️⃣ 一句话总结

> 广播的“逻辑复制”在底层被翻译成stride=0的技巧，
> 
> 
> 让同一个内存值在计算时被**多次复用**，
> 
> 既省内存，又能在并行硬件上高效执行。
> 

# 广播机制的用法

把 PyTorch 的广播规则记成一句话：

**“从尾部维度开始一对一对比较，要么相等，要么其中一个是 1，否则就报错。”**

---

### ✅ 一步一步看例子

### 1️⃣ 能广播的例子

```python
a = torch.randn(3, 1, 5)   # (3,1,5)
b = torch.randn(1, 4, 1)   # (1,4,1)
c = a + b                  # → (3,4,5)

```

- 从后往前：
    - 第 3 维：5 vs 1 → 可以
    - 第 2 维：1 vs 4 → 可以
    - 第 1 维：3 vs 1 → 可以
    → 结果自动扩展到 `(3,4,5)`。

---

### 2️⃣ 不能广播的例子

```python
a = torch.randn(3, 5)   # (3,5)
b = torch.randn(4, 5)   # (4,5)
# a + b  ❌  RuntimeError

```

- 第 1 维：3 vs 4（既不相等，也不是 1）→ 报错。

---

### ✅ 判断能否广播的 3 步口诀

1. **维度对齐**：先把两个张量维度个数补齐（在前面补 1）。
2. **从右往左**比较每一对轴。
3. 每对轴必须满足：
    - 长度相等 **或**
    - 其中一个长度为 1。

---

### ✅ 常见场景速查

| 场景 | 能否广播 | 说明 |
| --- | --- | --- |
| `(B,T,D) + (B,T,1)` | ✅ | 最后一维 1 → 自动复制 D 次 |
| `(B,T,D) + (D,)` | ✅ | 向量维度对齐尾部 |
| `(B,T,D) + (B,1,D)` | ✅ | 第 2 维 1 → 复制 T 次 |
| `(B,T,D) + (T,D)` | ✅ | 缺 B 维 → 视为 (1,T,D) |
| `(B,T,D) + (B,T+1,D)` | ❌ | T 不匹配且都不是 1 |
