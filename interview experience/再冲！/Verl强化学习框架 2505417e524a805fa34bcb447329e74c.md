# Rollout和Inference

- actor 在 RLHF 会进行 auto-regressive decoding，称为Rollout
- critic, reward 和 reference 则只会 prefill，不会 decode，称为Inference

# SPMD（single program multiple data）

这是一种典型的多卡训练范式：

- 所有的卡运行相同的一份代码
- 每个卡一个进程，进程会标识当前进程的RANK号，根据这个特殊的RANK号码，不同的机器执行不同的动作
- 每个RANK的机器都有自己的地址和端口号
- 某个机器会存在一个特定的group，group内初始化完毕之后，才会开始正式进行训练，组内可以进行通讯

```python
import torch
import os

print(os.environ['RANK'], os.environ['WORLD_SIZE'], os.environ['MASTER_ADDR'], os.environ['MASTER_PORT'])
torch.distributed.init_process_group(backend="nccl")
torch.cuda.set_device(torch.distributed.get_rank())
```

## SPMD情况下的TP

- 这里是按列把参数拆分了，在 PyTorch 里，`nn.Linear` 的权重张量形状是 **[out_features, in_features]**
- 每个设备有相同的输入
- torch.distributed.all_gather_intotensor(output_tensor, ret, async_op=False)
    - 将不同rank的卡上的ret，按照rank的顺序拼接到output_tensor的首维上

```python
# 我们用torchrun启动这段代码

import torch
import torch.nn as nn

torch.distributed.init_process_group(backend="nccl")
torch.cuda.set_device(int(os.environ['RANK']))

torch.manual_seed(42)
torch.cuda.manual_seed_all(42)

# 构建一个从column维度切分的linear layer
class ColumnTPLayer(torch.nn.Module):
    def __init__(self, input_size, output_size):
        super().__init__()
        self.layer = nn.Linear(input_size, output_size // int(os.environ['WORLD_SIZE']), bias=False).to(device='cuda')

    def forward(self, x):
        ret = self.layer(x.to(device='cuda'))
        output_tensor = torch.zeros(size=(int(os.environ['WORLD_SIZE']), ret.shape[0], ret.shape[1]), dtype=ret.dtype, device=ret.device)
        torch.distributed.all_gather_into_tensor(output_tensor, ret, async_op=False)
        output_tensor = torch.cat(output_tensor.unbind(dim=0), dim=-1)

        return output_tensor

    def load_weights(self, weight):
        rank = int(os.environ['RANK'])

        world_size = int(os.environ['WORLD_SIZE'])
        dim_per_rank = weight.shape[0] // world_size
        self.layer.weight.data.copy_(weight[rank*dim_per_rank: (rank+1)*dim_per_rank, :])

batch_size = 10
input_data = torch.randn(batch_size, 2)

# init一个PyTorch的linear layer，并让我们构建的layer和它保持参数一致。
full_layer = torch.nn.Linear(2, 6, bias=False)
weight = full_layer.state_dict()['weight']

tp_layer = ColumnTPLayer(2, 6)
tp_layer.load_weights(weight)

tp_ret = tp_layer(input_data).cpu()
fl_ret = full_layer(input_data).cpu()

torch.testing.assert_close(tp_ret, fl_ret)
```

## TP和DP的切换

verl中经常涉及到TP和DP的互换：

- 假设pipe line中3个model（1，2，3按顺序）
- 1，3进行DP，2进行TP
- world size是2（world size是总的进程数量）

1. model1： 进行DP得到 8个内容不一样的 (bz,d)
2. model2：进行TP，所有的GPU用同样的一个(8*bz,d)作为输入
3. model3：进行DP，每个GPU得到一个不一样的 (bz,d)作为输入

# DeepSpeed Zero123

1. zero1中，每张卡只需要保留1/n的optimizer参数，通信量保持不变
2. zero2在zero1的基础上，每张卡只需要保留1/n的graident，通信量保持不变
3. zero3在zero2的基础上，每张卡只需要保留1/n的model weight，通信量变为1.5倍

## 使用zero在Rollout的时候，会产生问题

- 如果使用zero3，那么每次自回归生成的过程中，都要把所有的参数都gather一遍，进行一次前向。
- 不使用zero3，又会爆显存

# 使用VLLM

推理和训练分开，问题：

- 推理的时候由于VLLM使用的算子不同
- 每次进行actor参数更新后，rollout engine需要更新
- VLLM不是原生支持SPMD的，有一个控制中心Driver
- VLLM的模型初始化需要改写：
    - layer命名不同
    - actor的tp策略和vllm的tp策略不一样

## 修改VLLM

- **不再由一个固定的Driver，将数据分发**

tp的情况下每个worker有完全相同的输入

```python
# 原Ray依赖逻辑
class RayWorker:
    def execute_model(self, inputs):
        return driver.dispatch(inputs)

# SPMD化改造后
class SPMDWorker:
    def execute_model(self, inputs):
        return self._model(inputs)  # 各worker独立执行
```

- **修改显存占用定义**

假设显存为80G，VLLM的GPU_utilization是0.5，VLLM会进行dummy_input获取kv cache可能占用的空间，假设是20G，那么实际上这个时候的显存占用是80*0.5+20=60G

Verl改成除去dummy_input剩下的显存空间的占用比例，也就是0.5 * (80-20)

- **从actor处重新加载权重**

[Fully Sharded Data Parallel (FSDP)](Verl%E5%BC%BA%E5%8C%96%E5%AD%A6%E4%B9%A0%E6%A1%86%E6%9E%B6/Fully%20Sharded%20Data%20Parallel%20(FSDP)%202555417e524a809b8e16d60da3d3eb1b.md)
